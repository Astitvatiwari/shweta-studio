# Staging verification checklist

1. **Automated database and browser checks:** The `Staging regression` GitHub Actions workflow starts an ephemeral PostgreSQL 16 service, runs all API/schema/security tests including real multi-connection races, installs Playwright Chromium, and runs cart/image browser checks. No Render database or credentials are needed for this CI run. It requires an approved push to the feature branch before it can execute.
2. **Optional local Render database:** If testing directly from a local terminal instead, follow the disposable Render database instructions in `backend-deployment.md`. It must be a free, test-only DB; restrict external access to the test runner's `/32` IP and never store customer or production data. Free Render Postgres expires after 30 days and has no backups.
3. **Browser and checkout checks:** Chromium verifies cart add-to-bag and thumbnails. The API suite verifies checkout pricing/reservations, signature rejection, failed payment hold release, and expiry; staging Razorpay checkout still requires test credentials and a staging backend.
4. **Staging services:** Before creating any Render or Netlify service, verify plan and cost. Set backend `NODE_ENV=production`, `STORAGE_BACKEND=postgres`, TLS, exact storefront origin, signed-proxy secret, and `DATABASE_URL`/migration URL. Use Razorpay test credentials only. Keep admin and database credentials server-side.
5. **Schema and connectivity:** Apply migrations to the staging database using the migration role; run health check, inventory reads, checkout reservation, Razorpay test checkout, valid/invalid webhook, failure/cancel, replay, and expired-hold scenarios. Confirm no order or customer information is available from unauthenticated routes.
6. **Frontend staging:** Deploy a Netlify branch preview with catalog-only build and API proxy set to the staging backend. Verify `x-nf-sign`, allowed origins, HTTPS, cart thumbnails, image paths, console/network errors, mobile layout, and the complete checkout journey.
7. **Review gate:** Capture test summaries, migration status, safe logs, and rollback/restore proof. Resolve all failures and review the security checklist before any production settings, merge, production deployment, or live Razorpay activation.

No staging service, credential, domain, webhook, or database has been created/configured by this repository.
